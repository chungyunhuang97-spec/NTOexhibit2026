# AI 去背測試機（無背板路線）

用 `@imgly/background-removal`（瀏覽器端 AI 人像分割）驗證「售票口周圍無法佈置實體背板」情境下的去背可行性。純 Canvas 色鍵去背版本不適用這個場景，這版才是對的技術路線。

## 為什麼要你自己部署

這個 demo 需要在瀏覽器裡即時下載 AI 模型檔案（來自 IMG.LY 的 CDN）。Claude 這邊用來出線上連結的協作環境會擋掉這類外部模型下載，所以沒辦法像色鍵去背那版一樣直接給你一個可以馬上點開的連結——這份原始碼是驗證過邏輯正確、可以直接動的，只是需要你自己的網路環境跑一次部署（大概 2-3 分鐘）。

## 部署方式（擇一）

### 方法一：用你自己的 Vercel 帳號（推薦，跟你 portfolio 用的是同一套流程）

```bash
cd ntu-ai-bg-removal
npm install
npx vercel --prod
```

第一次執行會問要不要登入、要建在哪個帳號／專案下，照著互動式問答走就好，跑完會直接印出一個公開網址，iPad Safari 打開就能測。

### 方法二：Netlify Drop（不用裝任何 CLI，最快）

```bash
cd ntu-ai-bg-removal
npm install
npm run build
```

跑完後資料夾裡會多一個 `dist/`，把整個 `dist` 資料夾拖進 https://app.netlify.com/drop ，幾秒內會給你一個公開網址。

## 使用方式

1. iPad Safari 打開部署後的網址
2. 允許相機權限
3. 點「啟動相機」→ 這時只是原始畫面，不做任何處理
4. 選場景 → 按下快門 → 對那張全解析度影格跑一次 AI 去背，畫面上會顯示**實際量測的處理耗時**
5. 上方「模型品質」「執行裝置（GPU／CPU）」可以現場直接切換比較——這兩個一起看，就是回答「這台展場 iPad 能不能吃得動、值不值得選 GPU 加速」的答案
6. 結果圖片長按可以直接存到照片圖庫

第一次拍照會下載模型檔（依網路速度可能要幾秒到十幾秒），同一台裝置之後瀏覽器會快取，會快很多。

## 已知限制

- 場景美術是程式產生的佔位色塊，不是最終視覺
- 沒有做離線快取（PWA／Capacitor），純粹先驗證去背可行性與速度
- GPU 模式若該瀏覽器不支援 WebGPU 會自動退回 CPU 並在結果畫面標示
